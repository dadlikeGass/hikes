# hikes · 山里见 —— 可运行原型

零构建的移动端 H5：原生 HTML / CSS / JS + hash 路由，没有依赖、没有打包步骤。

## 怎么跑

**最简单**：双击 `index.html`，用浏览器打开。

**推荐**（手机同局域网预览）：

```bash
cd app && python3 -m http.server 8080
# 然后打开 http://localhost:8080
```

手机访问：把 `localhost` 换成电脑的局域网 IP（例如 `http://192.168.1.5:8080`）。
浏览器窗口宽度 ≥ 600px 时会自动套一个手机外框，方便在桌面上看。

## 目录

```
app/
  index.html        外壳：顶栏 + 内容区 + 底部导航 + 弹层容器
  css/app.css       全部样式（设计令牌在 :root）
  js/data.js        演示数据骨架：线路 / 山头 / 岔路 / 动态 / 活动 / 消息
  js/routes.data.js 自动生成：28 条真实北京线路的 GPX（抽稀内嵌），改它请改生成脚本
  js/routes.real.js 真实内容包：把线路 / 山头 / 岔路 / 动态换成北京真实线路
  js/ui.js          工具：山景插画生成、图标、localStorage、弹层、toast
  js/track.js       轨迹解析 / 按坡度分段 / 海拔剖面 / 难度计算 / 标牌 / 二维码
  js/app.js         路由 + 每个页面的渲染与交互
```

## 真实线路数据

`js/routes.real.js` + `js/routes.data.js` 把演示内容换成了 **28 条真实北京线路**
（12 条山野徒步 / 越野 + 16 条公园跑步），轨迹抓自六只脚（foooooot.com）。
完整精度的 GPX 在仓库根的 `tracks/` 与 `tracks/parks/`，那里还有来源链接与数据说明。

数据口径（页面上的文字也跟着改了）：

| 字段 | 含义 |
| --- | --- |
| 六只脚人气 | 该轨迹在六只脚的浏览量，不是本地统计、也不是到访人数 |
| 参考用时 | 按 4.5 km/h 平路 + 每 600 m 爬升 1 小时估算，**不是真实纪录** |
| 爬升 | 海拔去噪后的累计爬升（原始 GPS 值会虚高 30%–50%） |
| 路况 | 没有可靠来源，统一留空让用户补充，不编造 |

公园跑道（`group === 'park'`）的详情页多一张**跑步参考**卡：
单圈距离、累计爬升、常见路面、以及 5:00 / 6:00 / 7:00 三种配速的换算用时。
配速是按距离直接换算的；路面是按各公园普遍路况的判断，没有逐段核实（GPX 里没有路面信息）。

想回到纯演示内容：删掉 `index.html` 里 `routes.data.js` / `routes.real.js` 两行即可。

重新生成（需要网络，抓六只脚公开接口）：

```bash
cd ../tracks && python3 make_gpx.py && python3 build_app_data.py
```

## 路由

| 路径 | 页面 |
| --- | --- |
| `#/` | 首页（左上角 logo 进入，不是 tab） |
| `#/trails` | 路书 tab |
| `#/trails/:id` | 线路详情（分段路书 / 用时榜 / 留言板） |
| `#/places` · `#/places/junction` | 山头·岔路 tab（顶部切换） |
| `#/peaks/:id` | 山头页 = 打卡点 |
| `#/junctions/:id` | 岔路页 = 路书点（往哪走 + 情报卡） |
| `#/messages` | 消息 tab |
| `#/me` 及 `#/me/visited` `want` `peak` `records` `letters` `activity` | 我 tab 与子页 |
| `#/scan` | 扫一扫（演示：点按钮模拟扫码，或输入点位编号） |
| `#/arrive/:peakId` | 扫码到达页（第 N 位 → 打卡 → 拆信 → 留言） |

## 可以真的操作的部分

打卡、收藏到想去、击掌、报名/退出活动、确认岔路情报、上报情报、发留言、
写未来信、发起周末活动、解决好友请求 —— 都会立刻生效并写进 localStorage，
刷新和重开浏览器都还在。

状态存在 `localStorage` 的 `hikes.v1.*` 键里；「我」页面底部有**清空我的演示数据**，
可以一键恢复初始状态。

扫码页是模拟的：点「青山顶 · 山顶打卡点」相当于扫到山顶的标牌，
点「林道岔口」相当于扫到岔路口的标牌，也可以手动输入 `QSD-02` 或 `QSD-100`。

## 这一版刻意的设计约束

- **扫码只在两处**：底部正中凸起 + 首页顶部窄条。不要在页面里再加第三个。
- **用时只在同一条线路内比较**，跨线路不排名。
- **岔路是情报，山头是情绪**：两类地点两种页面，不要合并。
- **每条通知都能回到现场**（地点上下文胶囊），而不是回到某个人的主页。
- 山景插画是按点位 id 确定性生成的（同一座山永远同一张图），没有外部图片依赖。

## 还不是真的

**线路与轨迹是真的**（28 条，来自六只脚，见上）。以下仍然是演示内容：

- 登录、真实 GPS、摄像机扫码、图片上传、推送、后端与数据库都没有；
- 人名、留言、用时榜、活动、消息、信件都是演示数据；
- 「人气 / 热度」用的是六只脚浏览量，「参考用时」是按距离和爬升估算的，都不是本站真实统计；
- 路况信息没有可靠来源，页面统一留空，不编造。
