# 路线剖面、方向难度与检查点维护

## 目标

让路线详情的剖面图可读、可信且可维护：用实际海拔展示线路，标出山峰和检查点；难度按单向行进的爬升段判定；允许有权限的路线关联山头维护人维护峰名和 CP 信息。

## 当前实现

- `pipeline/build.py` 将 GPX 重采样为约 100 米间隔，输出相对归一化的 `profile`、峰和路线分段。分段按峰之间切分，已生成 JSON 的下降段为 `easy`，但现有数据库还保留 `mid`/`hard` 的下降段。
- `server/app/main.py` 的路线详情 API 返回归一化剖面；峰响应没有峰名；CP 只读返回名称、里程、海拔、坐标和离轨距离。
- `route_peaks.name` 可为空，峰名候选表 `route_peak_candidates` 已存在；目前缺少用户提交、维护人确认的 API 与页面交互。
- `route_checkpoints` 已保存赛事 GPX waypoint，但没有补给类型、备注字段，也没有维护人新增入口。
- 维护人身份挂在路线关联的山头板上，而不是 `routes` 表上。

## 设计

### 海拔剖面

- 核心 GPX 产物增加以米为单位的 `elevation_m` 数组，与现有 100 米重采样距离点一一对应；保留 `profile` 兼容现有归一化图表消费者。
- 路线详情 API 返回真实高程数组、已有峰名和检查点补给字段。
- 剖面按实际里程与海拔绘制，显示公里横轴、米纵轴、起点/终点、峰顶海拔和峰名、CP 名称/类型。轴刻度按线路范围取易读的整百或整三百米间距。
- 未确认峰名显示“山顶 · 待命名”。用户提交峰名作为 `route_peak_candidates` 中的 `source=user` 候选；关联山头维护人确认后写入正式峰名，拒绝候选不覆盖已有名称。

### 单向难度

- 路线按行进顺序识别起点、平滑高程局部鞍部和峰顶，形成相邻的上升、下降、平缓段。只有鞍部/起点到后续峰顶的爬升段适用 easy/mid/hard 难度，并参与路线“最难段”计算。
- 增加 `difficulty_applicable` 标记；旧 `level` 字段保留兼容。下降与平缓段标为不适用，在剖面图中用中性色显示，不显示成“简单”难度，也不参与线路难度排序，即使旧记录曾被人工确认为困难。下坡风险若后续需要，作为独立字段另行建模。
- 爬升段使用其爬升高度与正向平均坡度判级；峰间净高差不作为含下降段的难度依据。
- 导入新算法结果时保留人工确认值；未确认旧下降段数据按新方向规则重算，避免数据库保留旧 `mid`/`hard` 标签。

### 山峰名维护

- 剖面峰标记显示海拔及已确认名称。点击待命名峰可提交候选名称；点击已命名峰可提交修订候选。
- 维护人确认/驳回候选后更新峰名状态和来源记录，页面显示当前确认名。自动地名匹配仅作为候选，不直接覆盖确认名。

### CP 维护

- CP 字段：名称、里程必填；补给类型、备注选填。海拔和经纬度按里程从已发布路线轨迹/高程剖面插值，不允许客户端任意填入不同位置。
- 路线关联山头板的维护人可新增 CP；其他用户只读。官方 GPX CP 和维护人手工 CP 都保留来源标记，重新导入赛事 waypoint 不得覆盖手工记录。
- API 与页面提供新增入口；新 CP 按里程排序，并在剖面上显示可点击标记及 CP 信息。

## 数据与 API 变更

- 路线产物/API：新增绝对高程采样数组；峰响应增加 `name` 与名称确认状态；CP 响应增加 `supply_type`、`notes`、来源字段。
- `route_checkpoints` 增加补给类型（自由文本）、备注、来源字段；旧 CP 数据迁移为官方来源。
- 增加用户提交峰名候选、维护人审核峰名，以及维护人新增 CP API；服务端按路线关联山头板验证维护权限。
- 难度数据模型明确区分“难度适用”和方向类型，下降/平缓不以 easy 标签冒充难度。

## 兼容与边界

- 保留现有归一化 `profile` 字段一段迁移期，其他页面不必同步改版。
- 不把维护人 CP 写入 `points`：CP 不产生二维码、山峰榜或独立留言板。
- 赛事官方打卡点继续按 GPX 计算位置；手工补充数据与官方来源可区分、导入时不互相覆盖。
- SRTM 地形底图继续与路线剖面独立生成；本次只在剖面上新增路线峰和 CP 标注。

## 验收标准

- 三峰剖面轴显示实际米数与公里数，5 个峰标记位于对应里程并显示海拔/名称状态，CP 标记显示名称与补给信息。
- 用户提交峰名后成为候选；关联山头维护人可确认或驳回，已确认峰名不会被自动管线覆盖。
- 三峰最后的下降段显示为下降中性色，数据库和页面均不再将其作为困难段；路线最难段从有效爬升段中选择。
- 有权限维护人可按名称、里程新增 CP，补给类型/备注可空；非法里程、无权限写入被拒绝；海拔和坐标由服务器按轨迹生成。
- 重跑 GPX/赛事检查点导入不删除维护人手工 CP，不覆盖人工确认峰名或难度。
