## 0. 与现有决策的冲突

本文纳入两处此前被排除的范围，需要用户确认后正式改回：

| 内容 | 现状 | 本文要求 |
| --- | --- | --- |
| 用时榜 | LAUNCH 要求"接真库或标待开发"；WEB_PRIORITIES 不展示登顶纪录 | 接真库，按本文口径发布 |
| 未来信 | PLAN 与 LAUNCH 的"不做"清单 | 回到范围，仅限「我」页一个模块 |

现有 schema 已有基础：`visits.source` 的枚举含 `nearby`，`visits.duration_sec` 注释为"填了才进最快用时榜"，`visits.seq` 已在发放，`letters` 表已存在。本提案是把预留位用起来，不是新建体系。

## 1. 什么榜

**只有一种榜：登顶用时榜。比较单元是「入口 → 山顶」这一对点位。**

明确不是榜、只是统计的东西：到访人数、第几位打卡、打卡次数。它们与榜分开计算、分开显示，不混排在同一模块里。

理由：用时是唯一同时具备明确起点、明确终点、明确方向和可比口径的量。次数与人数可以刷，用时不能。

不做：全站总榜、跨地点聚合榜、综合评分榜、星级评价。

## 2. 公开与私密

原则一句话：**公开"到过哪个地点、哪天、用了多久"，永不公开"你在哪、你从哪来、你怎么走的"。**

| 内容 | 默认可见性 | 说明 |
| --- | --- | --- |
| 昵称 | 公开 | 与留言板一致，沿用现有昵称 |
| 地点名称 | 公开 | 地理对象本身是公开信息 |
| 到访日期 | 公开，精确到日 | 不公开时分，避免被推断作息规律 |
| 登顶用时 | 公开 | 用时本身不暴露位置 |
| 名次、百分位 | 公开 | 受样本门槛约束 |
| 精确坐标、GPS 精度 | 私密 | 只用于判定打卡可信度与配对 |
| 轨迹、起点 | 私密 | 沿用现有 `tracks` 语义 |
| 打卡精确时刻 | 私密 | |
| 连续到访规律 | 不展示 | 可推断习惯，即使汇总也不展示 |
| 照片 | 私密 | 上一轮决定：照片私人，文字公开 |
| 未来信 | 永久私密 | 不可公开、不可分享 |

### 开关

- **上榜开关，默认开。** 关闭的含义是**完全退出榜与百分位统计（含分母）**，不是仅隐去名字。理由是隐私优先且行为可解释——不出现"榜上有个陌生位次"的困惑。
- 留言与纪念的公开开关沿用现状。

### 上榜资格

只有注册账号可上榜。游客的成绩当场可见，并在此处引导注册以保存与上榜——这正是"注册三个自然时机"之外新增的一个真实时机。

### 样本门槛

样本少于 8 时不显示名次与百分位，改显示"你是第 N 位完成者"。冷启动阶段（无配对成绩）只显示"有记录以来"的到访序号。

### 隐私政策

上线前必须同步更新 `/privacy.html`：新增上榜信息的公开范围、上榜开关、以及定位数据仅用于可信度判定的说明。

## 3. 展示位置

| 位置 | 形态 |
| --- | --- |
| 打卡凭证（山顶码扫开后） | 内联一行：我的用时 + 位次 + 百分位 |
| 路段页 | 完整小榜：前三名 + 我的一行；不折叠 |
| 山头页 | 汇总：该山各上登路段的榜首用时各一行，点入路段看完整榜 |

凡是榜都不进第一屏，唯一例外是打卡凭证里的"我的一行"——它本身就是凭证的组成部分。

首页不放任何榜。

理由：扫山顶码的情绪流是 认出地点 → 我到了 → 凭证 → 留言。榜属于比较性信息，插进这条流会打断情绪峰值；自己的成绩例外，因为它就是凭证的一部分。路段页与山头页的榜服务于出发前的行程比较，那里用户的注意力本来就在"选哪条路"上。

## 4. 未来信

范围严格限定为：**只在「我」页加一个模块，不做通知、不做邮件、不做独立页面、不做分享。**

- 未到期：只显示倒计时与写作地点，**不显示内容**
- 已到期：可打开，显示内容与写作时的地点
- 写新信：一句话 + 解锁时间，1 / 3 / 5 年三选一，默认 5 年
- 不做自定义日期选择器
- 账号注销时随个人数据一并删除

解锁的发现方式是**被动的**：未到期的信一直在「我」页显示倒计时，到期后该条变为可打开。不主动推送。

这是对户外人群反感打扰的直接回应，同时也创造了一次自然回访。

## 5. 打卡：两种来源与离线

扫码与定位是同一个打卡的两种证据来源，必须分级，因为排名依赖它。

| 来源 | 判定 | `evidence_level` | 可入榜 |
| --- | --- | --- | --- |
| 扫码 | code 命中点位 | `code` | 是 |
| 定位 | 在点位半径内且精度达标 | `gps_close` | 是 |
| 定位或补传 | 精度差、距离远、时间可疑 | `gps_far` | 否 |

半径按点位类型分别设定（山顶紧、山脚松），服务端校验，前端只传原始坐标与精度。

离线：现场在本机落一条 `{occurred_at, code 或坐标, GPS 若 20 秒内可得}`，网络恢复后提交，服务端以 `occurred_at` 入账。

两个必须处理的细节：

1. **`visit_date` 取 `occurred_at` 的日期，不能用 `CURRENT_DATE`。** 现有唯一约束是 `UNIQUE(user_id, point_id, visit_date)`，周末爬山工作日补传会被算错日期，序号与"本周"统计同时失真。
2. **序号按服务端入账顺序发放**（避免离线补传插队），而到访时间与排名用 `occurred_at`。两者不冲突，且都可解释。

离线打卡在文案上不得承诺过头：页面本身需要能被打开，无网时可用的前提是页面已被缓存。

## 6. 排名口径

**比较单元是「起点点位 → 终点点位」这一对，不是山峰，也不是完整线路。** 同一座山的不同入口长度与爬升不同，混排无意义。这要求布点按上登路段的两端成对规划，而不是按景色规划。

配对规则：同一身份先有起点打卡、后有终点打卡，间隔不超过 12 小时，跨日拒绝。

生成时机：终点打卡时由服务端配对并写入 `segment_efforts`，**不在查询时现算**。

只有 `evidence_level` 达标的配对入榜；人工填写的 `duration_sec` 不入榜。

三个展示数字的口径：

| 展示 | 算法 | 保护 |
| --- | --- | --- |
| 前三名用时 | 按 `duration_s` 升序取 3 | 显示昵称与日期，不显示具体时刻 |
| 我的位次 | 比我快的人数 + 1 | 样本 < 8 不显示 |
| 我的百分位 | 比我慢的人数 ÷ 样本 | 样本 < 8 不显示 |

统计窗口：本周（ISO 周一）、本月、本年、有记录以来，按 `occurred_at` 计算，一次请求返回全部窗口。

反作弊三条：用时下限校验（低于合理速度上限拒绝入榜）、同一天同一人同一对只取最快一次、被排除的记录写明原因留痕以便复查。

## 7. 数据与接口影响

### 新增字段

`visits`：`occurred_at`、`recorded_at`、`position_source`、`lat`、`lng`、`accuracy_m`、`evidence_level`、`client_uuid`（幂等键）。

`comments`：`observed_at`（观察时间，与留言时间分开）。

`letters`：`unlock_at` 改为时间戳、增加 `delivery_channel`、`status`。

### 新增表

`segment_efforts`：配对后的成绩。

```
id, user_id, start_point_id, end_point_id, direction,
start_visit_id, end_visit_id, start_at, end_at, duration_s,
evidence_level, is_public, excluded_reason, created_at
UNIQUE (user_id, start_point_id, end_point_id, start_at)
INDEX (start_point_id, end_point_id, duration_s)
```

### 接口

- `GET /api/points/nearby`：按坐标查询半径内点位，返回距离与建议半径
- 打卡接口：支持 `scan` 与 `nearby` 两种来源、`client_uuid` 幂等、离线补传
- 序号接口：返回有记录以来 / 本周 / 本月 / 本年
- `GET /api/segments/{start_point_id}/{end_point_id}/leaderboard`：一次返回四个窗口的样本量、前三与我的一行
- 留言：公开留言与未来信两个入口

## 8. 兼容与边界

- 现有 `seq` 与打卡行为不变，只增字段，不改语义
- `duration_sec` 保留，但仅作手工填写的历史数据，不参与榜
- 定位数据可删除，符合 P10
- 不引入地图与轨迹可视化，榜只呈现数字与昵称
- 榜不阻塞打卡：榜查询失败不影响打卡与留言

## 9. 验收标准

1. 游客扫山顶码，无注册即可看到地点、完成打卡、看到自己的到访时间与用时（若有）
2. 关闭上榜开关后，该用户不出现在任何榜，也不计入百分位分母
3. 不同入口的用时互不混排；同一山顶可并列展示多条路段的榜
4. 样本少于 8 时不出现名次与百分位
5. 低速可疑成绩被拒绝入榜并留有排除原因
6. 同一天同一人同一对只产生一条成绩
7. 离线补传以 `occurred_at` 入账，`visit_date` 归属正确，同一 `client_uuid` 重复提交只产生一条到访
8. 未到期的未来信在任何接口与页面都不返回正文
9. 精确坐标与轨迹不出现在任何公开响应中
10. 榜查询失败时打卡、留言、凭证三项功能不受影响
