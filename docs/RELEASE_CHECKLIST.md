# 小程序发布验收

本清单区分代码准备和线上验收；模拟器通过不代表真机通过。

## 本轮代码

- `server/app/content_safety.py`：微信文本审核 v2；只接受明确 `pass`，风险/人工复核建议均拒绝公开，服务异常返回可重试错误；不保存或打印凭据、提交原文。
- 点位留言、路段留言、回复、到访草稿发布及新建点位附带的介绍经过审核。私人草稿不送审，审核失败不删除草稿。
- 未配置微信凭据或账号没有微信身份时，以上公开发布会被阻止。这也影响使用同一 API 的 H5 账号；上线前必须完成身份绑定策略及真实账号验收。
- 岔路/路段详情补上举报操作；原有点位和路书详情继续复用同一组件。
- 新增 `/app/reports.html` 举报处理台；先在同源 H5 登录，再由已有 `content_reviewer` 角色账号处理。服务端检查权限、禁止自审、要求理由并记录审计。前端没有授予角色的功能。
- 人工审核的山头申请、广告、以及其他公开资料不应被误认为已全部接入自动机审；发布前由运营逐项核对其审核流程。

## 用户负责的配置

微信登录凭据、request 合法域名、主体与备案、服务类目由账号负责人完成。凭据只存服务器环境，不提交 Git。微信安全接口的调用权限及 IP 白名单须在真实联调时核对。

## 服务器上线门槛

1. 记录部署的 Git 提交；先检查 `alembic current`，仅落后时运行迁移。不要凭本地未跟踪状态判断生产库未执行。
2. 部署后检查根路径 `/health`，并检查 `/api/routes`、`/api/summits`；`/api/health` 不是健康接口。
3. 真实微信账号验证登录、退出、游客记录合并、注销身份复验。
4. 验证审核通过可公开；风险、待复核、限流、超时均不公开且草稿仍在；过期服务令牌下次调用能够重新获取。
5. 验证点位/路段/岔路举报进入处理台；普通账号被拒绝；审核员受理/隐藏后公开列表不再显示，处理理由有审计记录。指定实际运营负责人及处理频率。
6. 检查所有公开输入：昵称、点位名称/介绍、留言/回复、广告、申请通过后展示的字段。自动审核和人工审核的覆盖边界必须明确。

## 体验版与真机（待真实设备执行）

先上传体验版，每项记录设备/系统、版本、预期、实际结果和证据：

- iOS / Android 扫码及相册识别、取消扫码、手动点位码。
- 游客到访、登录后合并、相同 UUID 重试不产生重复记录。
- 断网/弱网重试、过期 JWT、退出后身份隔离。
- 私人草稿及公开留言草稿在断网、重启后的恢复。
- 隐私同意/拒绝，未授权时可继续允许的浏览功能。
- 注销成功、身份不匹配拒绝；不使用生产重要账号做破坏性验收。
- 举报完整处理链路；公开留言审核失败不丢输入。
- 当前页导航选中态、长文本、空列表、加载与错误重试。

## 本地验证命令

```powershell
python server/tests/test_content_safety.py
node apps/taro/tests/app-contracts.test.cjs
node apps/taro/tests/slope.test.cjs
cd apps/taro
npm run typecheck
npm run build:weapp
```

构建会先删除 dist，需在允许构建子进程的环境运行；失败须立即修复并重建。页面验收使用工作区 `.tools/weapp-agent-mcp/verify-design.mjs`。MCP 使用 connect 模式与显式 `ws://127.0.0.1:9420`，项目路径为 `apps/taro`。

上述本地测试不能证明真实微信审核服务、生产数据库、真机权限或审核员运营流程已经验收。
