# 到此一游 · 1.0 开发计划

> 本文档是 1.0 的施工图：范围、UI 冻结、页面结构、功能设计、后端结构、数据表、里程碑与验收标准。
> 关联文档：[API 契约](./API.md)

## 一、目标与范围

### 北极星

1.0 不是"做完产品"，是**验证三件事**：

1. 用户会不会**扫码**（实体标牌前）
2. 用户会不会**留言**（到了之后有没有话想说）
3. 用户会不会**反复打开**

一切取舍以"能不能拿到这三个数据"为准。

### 范围

| 保留（1.0） | 延后 |
| --- | --- |
| 扫码识别点位、打卡、第 N 位 | 照片上传（OSS/签名/审核，工程量最大且不验证假设） |
| 文字留言 + 赞 / 踩 | 站内信、好友、求合影、组队 |
| 路书（列表 / 详情 / 分段着色 / 山顶） | 活动报名 |
| 岔路情报 + 核验 | 消息中心 |
| 用时榜、山径拼图、我的 record | 真实地图（先用 SVG） |
| 我去过的地方、未来信 | 小程序（W6 再上） |
| 首页、维护台 | |

### 三端节奏

- **H5 先行**（W1–W5），微信里直接打开，香港节点免备案
- **维护台**（W5）桌面 Web，内部使用
- **小程序**（W6 后）看回访数据再决定，用 Taro 复用 80% 逻辑

## 二、UI 设计风格（冻结，不改）

沿用现有 `app/css/app.css` 的设计令牌，实现时直接搬进 `packages/ui`。

### 色板

| 用途 | 值 |
| --- | --- |
| 页面底 · 暖白 | `#F7F3EC` |
| 卡片 · 纸白 | `#FFFFFF` |
| 主文字 · 墨 | `#22242E` |
| 次文字 | `#6B6E7E` |
| 品牌 / 扫一扫 · 钴蓝 | `#3455F5` |
| 行动 / 印章 · 珊瑚橙 | `#FF714E` |
| 信件 · 淡紫 | `#7B6CE8` / 底 `#ECE9FB` |

### 难度四色（形状 + 颜色永远同时出现）

| 档位 | 形状 | 颜色 | 值 |
| --- | --- | --- | --- |
| 简单 | 圆形 | 蓝 | `#2563EB` |
| 中等 | 三角形 | 黄 | `#F2B62C` |
| 困难 | 菱形 | 红 | `#E4453A` |
| 隐藏 | 六边形 | 黑 | `#22242E` |

**隐藏档只能人工设定，系统不自动产生。** 需不需要绳索冰爪、要不要手脚并用，交给山友和维护人。

### 造型规则

- 卡片圆角 22 px（大卡）/ 18 px（瀑布流）/ 13–16 px（小卡）
- 阴影 `0 1px 2px` + `0 8px 24px`，透明度 ≤ 7%
- 触控区 ≥ 44 px；正文 15 px，次要 13 px，卡片标题 19–22 px
- 手写体只用于信件与到访卡的一句情绪文案，**不碰功能文字**
- 底部导航 5 格：路书 / 山头·岔路 / 扫一扫（凸起）/ 消息 / 我；**首页走左上角品牌 logo**

## 四、功能设计（逐页）

### 首页
品牌条（居中，左上角可点回首页）→ 扫码窄条 → 热门线路轮播卡 → 周末组队活动卡 → 照片瀑布流。

轮播卡：左上角线路名 + 距离/爬升/用时；右上角收藏；右下角难度徽标；
下方左侧 SVG 轨迹缩略图，右侧「本周打卡人数 / 最快登顶 / 记录保持者」。
**轮播 5 秒自动播放，用户手动滑动后停止。**

### 路书
搜索框 → 难度筛选 chips（蓝/黄/红/黑四色）→ 各榜单横滑 → 关于难度（含中美瑞对照）→ 底部难度说明。

**用时只在同一条线路内比较**，每条线路各自成榜，跨线路不排名。

### 线路详情
大图 → 名称 + 距离/爬升/下降 + 识别到的山顶数 → **难度判定卡**（累计爬升 / 累计下降 / 持续坡度 三项各自定档取最高）
→ 标牌预览 → **按难度着色的 SVG 轨迹图**（山顶标海拔）→ 海拔剖面 + 色带 → 分段表（每段带留言入口）→ 维护人确认按钮。

### 山头页（打卡点）
山顶大图 → 海拔 + 所属线路 + 近 30 天到访 → 用时榜 → 照片墙 → 留言板 → 底部「收藏到想去 / 我也到了」。

### 岔路页（路书点）
来向视角大图 → 编号 + 属于哪条线路 + 第几个点位 → **「你在这里 · 往哪走」**（照片 + 箭头 + 一句话 + 下一段距离爬升）
→ **岔路情报卡流**（已核验 / 待核验 + 确认人数）→ 上报一条情报 → 顺路打卡（次要按钮）。

**岔路是情报，山头是情绪。** 两类点位两套页面，不合并。

### 到达页
`#N` 印章 → 「你到了，山友」→ 留下到访卡 → 三小格（首次 / 用时 / 拼图 +1）→ 用时榜一行 → 拆信 → 留言板 → 折叠趣味区。
**扫码后 3 秒内必须能完成打卡**，凡是需要读和决定的全部往后放。

### 消息
互动 / 请求 / 信件 / 系统 四组。每条带**地点上下文胶囊**，点击回到现场而不是某人的主页。

### 我
头像 → 山径拼图 → **我的 record**（爬过的山峰 + 登顶时间）→ 我去过的地方（地图/拼图/列表）→ 想去 → 我的山头 → 山间信箱 → 发起活动。

### 维护台（桌面）
点位台账（我维护的 / 待处理 / 未认领）→ 单点位管理：二维码（编号 + 短链 + 预览 + 重新生成）、标牌预览、子页面内容、**难度判定**（单段爬升比 + 地形方式）、动态内容核验、发布与版本记录。

**二维码里印短链，不印页面地址。** 编号一旦发布即锁定，页面内容随时可改。

## 六、数据表（PostgreSQL 15 + PostGIS 3）

### users
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigserial PK | |
| wx_openid / wx_unionid | text UNIQUE | 小程序 openid / 跨端 unionid |
| nickname / avatar | text | 允许为空，扫码后补 |
| created_at / last_seen_at | timestamptz | `last_seen_at` 用来算回访 |

### points（点位，打卡点 + 路书点 + 起点）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigserial PK | |
| code | text UNIQUE | **生成后不可变**，二维码里印的就是它 |
| type | text | `peak` / `junction` / `trailhead` |
| name / route_id / index_in_route | | |
| level | text | `easy/mid/hard/hidden`，hidden 仅人工 |
| altitude | int | 仅山峰 |
| geom | geometry(Point,4326) | 空间索引 |
| guide | jsonb | 往哪走：箭头 / 标题 / 说明 / 下一段 |
| maintainer_id | bigint → users | 认领人 |
| status | text | `draft` / `published` |
| version | int | 版本记录 |

### routes / route_segments / route_peaks
| 表 | 关键字段 |
| --- | --- |
| routes | id, name, sub, km, up, down, level, `geom geometry(LineString,4326)`, `path jsonb`（归一化坐标，喂前端 SVG）, `profile jsonb` |
| route_segments | route_id, no, from_km, to_km, km, rise, pct, level, kind(climb/desc/flat), `source`(auto/manual), `confirmed`, `geom` |
| route_peaks | route_id, index, km, altitude, rise |

**`up` / `down` 必须用原始高程 + 3 m 滞回计算**，不能用平滑后的高程（已踩坑）。

### visits（打卡）
| 字段 | 说明 |
| --- | --- |
| id, user_id, point_id | |
| seq | 第 N 位 |
| visit_date | date，**唯一索引 `(user_id, point_id, visit_date)`** 实现"一天一次"去重 |
| source | scan / nearby |
| created_at | |

### comments / comment_votes
| 表 | 关键字段 |
| --- | --- |
| comments | id, point_id, user_id, text(≤200), like_count, bad_count, status(normal/flagged), created_at |
| comment_votes | comment_id, user_id, value(like/bad)，唯一索引 `(comment_id, user_id)` |

**排序与 flagged 由服务端算**：维护人置顶 → 净分 → 时间；`bad ≥ 3 且 bad > like` 置 flagged，只灰不删。

### scans（扫码记录，验证第一个问题）
| 字段 | 说明 |
| --- | --- |
| id, point_id, user_id(可空), ua, ip_hash, created_at | 扫码即写，不管有没有打卡 |

### events（埋点）
| 字段 | 说明 |
| --- | --- |
| id, user_id, name, props jsonb, created_at | 三个验证指标全从这张表出 |

### comments 之外还需要：letters（未来信）、intel（岔路情报）、short_links（短链映射）

`short_links`：`code → point_id`，做 302 用。**这是标牌不用重印的关键。**

### 三个问题的判定线（W2 之后每周看）

| 问题 | 指标 | 判定线 | 不达线怎么办 |
| --- | --- | --- | --- |
| 会扫码吗 | 单个点位周扫码去重人数 | ≥ 30 | 换点位、换标牌位置/文案 |
| 会留言吗 | 留言人数 / 扫码人数 | ≥ 15% | 改落地页第一屏（放别人的留言做示范） |
| 会回访吗 | 7 日内二次打开（按 user 去重） | ≥ 20% | 加回访钩子（"你的留言被 3 个人看到了"） |

## 八、风险与依赖

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| **实地点位没人标** | W2 之后全部内容卡住 | 这是最长的非技术关键路径，现在就要安排人 |

### 我的边界

**能做**：全部代码、DDL、契约、文档、测试脚本、部署脚本、设计稿。
**做不了**：账号注册与认证、云资源开通、真机测试、实地踩点、内容审核、最后点发布。

节奏是：我每轮交付可运行代码 + 验证方法 → 你跑一次给反馈 → 我接着做。等待主要在你这边。
