## 三、数据模型调整（alembic 0010–0013）

当前迁移头：`0009_mountain_profile`。四个迁移互相独立，可单独回滚。

### 0010 · 打卡证据 `visit_evidence`

`visits` 表增字段。**`source` 不新增**——它的枚举 `('scan','nearby','manual')` 里本来就有 `nearby`，直接用。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `occurred_at` | `timestamptz` | 现场时间。本机产生，可能不准 |
| `recorded_at` | `timestamptz` | 服务端入账时间，默认 `now()` |
| `lat` / `lng` | `numeric(9,6)` | 定位打卡才有。不公开 |
| `accuracy_m` | `int` | 定位精度，用于判定可信度 |
| `evidence_level` | `text` | `code` / `gps_close` / `gps_far`，默认 `code` |
| `client_uuid` | `text` | 幂等键，本机生成 |

索引：`(point_id, occurred_at)`；幂等唯一索引 `(coalesce(user_id, guest_id), client_uuid)`。

两个必须落进代码的口径：

- **`visit_date` 取 `occurred_at` 的日期**。现有同名约束是 `(user_id|guest_id, point_id, visit_date)`，用 `CURRENT_DATE` 会让周末爬山、工作日补传的记录算错日期，序号与"本周"统计一起失真。
- **回填**：历史行 `occurred_at = created_at`、`recorded_at = created_at`、`evidence_level = 'code'`。

### 0011 · 登顶成绩 `segment_efforts`

新表。配对结果落库，**不在查询时现算**。

```
id, user_id, start_point_id, end_point_id, direction,
start_visit_id, end_visit_id, start_at, end_at, duration_s,
evidence_level, is_public, excluded_reason, created_at
```

- 唯一键 `(user_id, start_point_id, end_point_id, start_at)`——同一天同一对只留一条
- 索引 `(start_point_id, end_point_id, duration_s)`——榜的主查询
- `direction` 固定 `ascending`（登顶）

### 0012 · 信 `letter_delivery`

`letters` 表改造。现有字段：`user_id`、`point_id`、`text`、`unlock_at`、`read_at`。

| 变更 | 说明 |
| --- | --- |
| `unlock_at` 由 `date` 改 `timestamptz` | 三种解锁模式需要时间精度 |
| 增 `unlock_mode` | `date` / `checkin` / `open` |
| 增 `recipient` | `later`（留给后来的人）/ `self`（留给未来的自己） |
| 增 `status` | `sealed` / `unlocked` / `deleted` |

**注意**：`recipient = 'later'` 是"一对多被读到"的公开内容，需要跟留言一样进内容治理（举报、隐藏、申诉）。这一条影响接口设计，见 §九待确认。

### 0013 · 留言观察时间 `comment_observed_at`

`comments` 增 `observed_at timestamptz`（可空），与 `created_at` 分开。回填为 `created_at`。

## 五、页面调整（全部在 `app/`）

### 首页 `#/home`（`app/js/app.js` · `homeView`）

| 位置 | 模块 | 内容 |
| --- | --- | --- |
| 主视觉之下、功能格之上 | **到访次序 · 人数**（D4） | 一行一座山：山名 · 累计到访人数 · 我的次序 · 最近到访时间。按我到访时间倒序。**不做热度筛选，不打"最热门"标记** |
| 页面最底部（底部导航之上） | **我的打卡凭证**（D5） | 最近若干次到访：地点 · 到访时间 · 第 N 位 · 本次用时（若有）。游客显示本机凭证 |

### 占山为王页 `#/places`（`placesView`）

| 位置 | 模块 | 内容 |
| --- | --- | --- |
| 占山为王卡片下面（D3） | **登顶用时榜** | 上：我的一次成绩（用时 / 位次 / 百分位）；下：选中山头的各上登路段前三名。未选中山头时只显示我的成绩并提示"选一座山看它的榜" |

榜单口径三条硬规则：比较单元是「入口 → 山顶」这一对点位，不跨入口混排；样本 < 8 不显示名次与百分位；低可信成绩不入榜。

### 我页 `#/me`（`meView`）

入口已存在，现在标着"待开发"：`rowlink('#/me/letters', '✉', '山间信箱 …')`。

| 变更 | 说明 |
| --- | --- |
| 去掉「待开发」标记 | 接真数据 |
| 加解锁模式与收件人选择 | 写新信时三选一 + 两个收件人 |
| `#/me/letters` 视图 | 未到期只显示倒计时与地点，**不显示正文** |

### 到达页 `#/arrive/:code`（`arrivalView`）

打卡成功后展示：第 N 位 + 本次用时（若有）+ 位次与百分位。这是 D5 凭证的数据来源。

### 暂不做

- 山顶页 / 路段页的榜（用户已把榜放在占山为王页）
- 首页任何与用时有关的内容（用时榜与次序/人数榜严格分开）

## 八、风险与对策

| 风险 | 对策 |
| --- | --- |
| 用时榜因缺起点数据长期为空 | **定位打卡可当起点**（§六 W2），不必先在山脚贴码；空态文案写清缺什么 |
| 排名零和，必然有人刷 | 未注册不上榜；用时下限校验；同日只取最快；排除原因留痕 |
| 山区定位阈值拍脑袋误判 | 先现场实测再定阈值，走配置不硬编码 |
| 离线时间被改 | 序号按服务端入账顺序；时间可疑的记录标 `gps_far` 不入榜 |
| "留给后来的人"的信变成无治理的公开内容 | 要么进内容治理（举报/隐藏/申诉），要么本轮只做 `recipient = 'self'`，见 §九 |
| 封存的前端被脚本重新写回服务目录 | W7 加护栏，或封存期间不运行 `extract_design.py` |

## 九、待你点头（三条，其余都已定）

1. **首页模块的具体形态。** 我的定稿是：一行一座山（山名 · 累计到访人数 · 我的次序 · 最近到访时间），按我到访时间倒序，不做热度筛选。如果你要的是"按到访人数排前几名的山头榜"，说一句我改。
2. **未来信要不要"留给后来的人"这个收件人。** 你现有的 `#/me/letters` 页面已经画了「收到的信」，所以方向是通的；但这一维度是**一对多公开内容**，要做就得配举报、隐藏、申诉。本轮只做"留给 5 年后的自己"可以省一整套治理，你定。
3. **占山为王页那个榜的取数方式。** 我的定稿是：跟随该页当前选中的山头；未选中时只显示我的成绩。如果你要的是全站"本周各山最快"这种跨山榜，它和"同入口才可比"的口径冲突，得先改口径。
