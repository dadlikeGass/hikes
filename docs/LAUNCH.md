## 二、上线形态

- **H5**，香港/新加坡节点（免备案），域名 + HTTPS。
- 二维码内容 = `PUBLIC_BASE_URL` + `/p/{code}`；微信扫 → 302 到落地页。
- **ICP**：1.0 不依赖它。但注意因果关系——**一旦要做微信一键登录，ICP 备案就从"可并行"变成"必须"**（微信要求网页授权域名已备案，且服务器在国内）。
- 「不做」清单（写进文档，避免上线前反复）：小程序、微信登录、手机号注册、支付、照片上传、组队活动、未来信、山友动态流。

下表保留基础角色边界；更完整的权限、协作、试任和激励设计见 [PERMISSIONS.md](PERMISSIONS.md)，其新增细则属于提案，不表示已上线。

| 能力 | 游客 | 注册用户 | 维护人 / 山大王 | 运营 |
| --- | --- | --- | --- | --- |
| 看路书 / 山头 / 留言 | ✅ | ✅ | ✅ | ✅ |
| **打卡（带时间戳的到此一游凭证）** | ✅ | ✅ | ✅ | ✅ |
| 留言 · 起称呼 · 关注 · 山径拼图 · 消息 | ❌ | ✅ | ✅ | ✅ |

## 四、注册与登录（本轮定稿）

- **账号 = 用户名 + 密码**；邮箱**可选但推荐**（用于找回密码与邮箱验证）。
- **不做手机号**（短信成本 + 实名报备 + 到达率，三样都亏）。微信登录等资质到位后再接——同一账号挂多种登录方式是标准做法，`users` 表的 `wx_openid` / `wx_unionid` 已经预留。
- 技术要点：密码用 **argon2 或 bcrypt** 哈希（明令禁止明文/MD5）；登录**双限流**（按 IP + 按账号）；找回密码走**邮件一次性链接**（不做明文找回）；会话沿用现有 JWT。当前已实现 Argon2、IP/账号限流和 JWT；邮箱验证、一次性找回邮件尚未实现，不得将 dev-login 用于公开认证。
- **注册只在三个地方触发**：留言、起称呼、跨设备保存记录。浏览和打卡**永不拦**；游客打卡本身已经保存，不应通过文案暗示此前记录无效。
- **注册／登录后自动合并游客记录**：注册、登录与合并在同一数据库事务内；发布留言草稿仍需用户明确操作。数据库迁移与端到端验收状态见 PLAN.md，不以接口存在代替通过。
- **第 3 步本地验收（2026-10-13）**：Docker 接口联测覆盖游客令牌重试、同日打卡去重、草稿恢复、注册时原子合并、署名发布、丢失响应后的发布重试、私人纪念保留和再次登录；浏览器实测了扫码页到注册回跳与发布、服务中断后本机保留和恢复补存、首次数据加载失败后重试。临时记录已清理。真机/微信扫码与跨设备浏览器仍待部署后现场验收，不能把本地测试等同于上线验收。

## 六、数据与内容准备

- **先只放实地确认过的点位**。946 个沿途山顶没名字，一次放出去用户扫到一半是空白。
- **命名原则不变**：宁可「名称待定」，不许猜。维护人命名后，用户的历史记录会自动显示新名字（记录挂在点位 id 上）。

## 九、内容采集与 AI 模仿边界（方案已写，整体未实施）

- 公开线路与页面一旦可访问，无法保证别人或 AI 不复制布局、文字或功能；`robots.txt` 只能约束自愿遵守的爬虫，不是防护墙。账号草稿、私人纪念、维护任务和审核数据必须始终由服务端鉴权，不下发给游客。
- 上线最低控制：公开列表分页与单 IP/账号速率限制，异常批量抓取按阈值降速或封禁；扫码、留言与注册采用更严格的写入限流。静态角色素材保留原始文件与版权记录；公开图片可加轻量来源标识，但不破坏正常阅读。
- AI 工具仅可通过与普通游客相同的公开页面/只读接口读取获准内容；不提供绕过登录、批量导出或抓取私人数据的特殊入口。是否允许搜索引擎及 AI 爬虫收录各类公开内容，需要上线前逐类决定并写入站点政策。
- 验收：普通山友能正常浏览和扫码；批量请求会被限速且有日志；未授权访问私人/审核数据返回 401/403；对外不宣称“完全防爬”或“防止 AI 模仿”。
- 2026-10-14 起：注册/登录、新建游客身份、留言/情报、打卡、举报都接入了按身份＋IP 的写入限流，命中写入 `rate_limit_events` 供审计；生产 Nginx 转发的客户端 IP 已显式接入这些限流。**公开读取接口限流、异常批量抓取识别与素材来源保护尚未实施**，仍不能称为反爬验收通过。

## 十、这次定下来的规则（需回填进 PLAN.md §4 / API.md）

1. 游客：只能**看 + 打卡**（产出带时间戳的到此一游凭证）；留言 / 称呼 / 存记录 → 注册。
2. 扫码落地页模块顺序：**凭证（时间戳 + 第 N 位 + 海拔 + 线路位置）→ 三个可选动作 → 注册引导**。
3. 山顶 / 岔路 / 路段三类留言板：**每板一个广告位，默认第一屏之外**；维护人上传、系统审核，优质可系统提升首屏。取消按等级增加单板广告位；广告质量、共同维护与布局细则见提案。
4. 首页广告轮播位在「热门线路轮播」与「周末有人组队」之间；路书页在「热门线路」与「全部路线」之间。
5. 路段留言板是三类核心板之一，路书与独立路段页共享内容；旧版“备注仅加字段、非核心”描述已被替代。对象、方向、迁移与 API 改造待排期，本轮不宣称实现。
6. 「名称待定」不是缺陷，是必经状态。
7. 游客闭环接口：游客打卡、草稿保存/恢复、注册或登录时原子合并、账号草稿取回和用户明确发布均已实现并通过 Docker API 与本地浏览器联测；服务中断后本机草稿保存与恢复重试也已验证。实物标牌、手机/微信和移动网络现场验收按 PLAN.md 跟踪。维护协作、待核验任务队列及广告审核仍未完成。
