# 到此一游 · 开发原则

> 这些是硬约束，不是建议。每条都写了**怎么判断有没有违反**。
> 关联：[PLAN.md](./PLAN.md) · [API.md](./API.md)

---

## 一、你定的四条

### P1 · 严格按计划和文档开发

实施以 `docs/PLAN.md` 和 `docs/API.md` 为准。文档没写的，先补文档再写代码。
开发中发现问题，**改文档 → 再改代码**，不允许代码和文档不一致。

**怎么判断违反**：代码里出现文档里没有的接口、字段、页面，或文档里的约束
（比如"用时只在同线路内比较"）没落到代码里。

### P2 · 不浪费 token

token 浪费在"探索—推翻—重写"的循环里，不在写代码本身。具体做法：

- **先读文档再动手**，不重复探索同一个问题
- **一次交付完整可运行的东西**，不做半成品来回确认
- **大文件用结构化改动**，不整文件重写
- **先讨论定方案再写代码**，不边写边试
- **不把能自己验证的结果贴回对话**（跑一遍、看一眼就行）
- **一个问题只答一次**，不反复确认已经明确的事

**怎么判断违反**：同一处改了三遍以上、交付里有过半是重复内容、为一个小改动重建整个文件。

### P3 · 必须校验合格

**没有验证方法的交付等于没交付。** 每个交付必须附带"你怎么验证"：
一条命令、一个可打开的页面、一个断言，或一个给你真机跑的操作步骤。

里程碑验收以 `PLAN.md` 第七节的验收标准为准，**不达线不算完成**，不许"先上再补"。

**怎么判断违反**：我说"完成了"但你说不出怎么验证；或者验证方法是"你自己看看"。

### P4 · 面向 1 万用户的设计，但留好升级路

**现在不做的**：微服务、消息队列、读写分离、分库分表、多级缓存、
容器编排、自建 CDN、GraphQL。

**现在就要做对的**（这些以后改代价极大）：

- 表的**主键、唯一索引、外键关系**一次定对
- **点位 code 生成即不可变**，短链层独立
- 难度分级算法**只在服务端一份**
- 所有表结构变更走 **alembic 迁移**，不准手改库
- 接口**分页用游标**，不用 offset（数据量上来后 offset 会拖垮）
- 关键查询字段**预埋索引**（`geom`、`visit_date`、`created_at`）

**怎么判断违反**：出现只能在单机跑、换台服务器就要改代码的写法；
或者为了"以后可能用到"引入了现在不需要的组件。

## 二、我补充的六条

### P5 · 契约先行

`API.md` 是唯一真相。改接口的顺序永远是：
**改契约 → 改服务端 → 改前端（两端）**。

因为我们是小程序 + H5 + 后端三方并行，契约不同步就会三方漂移。

### P6 · 算法只算一次，且只在服务端算

难度分级、累计爬升、分段、山顶识别，**只存在于 `pipeline/` 和服务端**。
前端只负责渲染服务端给的结果。

绝不在前端算难度——否则小程序和 H5 会算出两个不一样的结果，
而且以后改算法要同步改两端。

**怎么判断违反**：前端代码里出现"爬升/距离"这类计算。

### P7 · 平台差异关在适配层

扫码、地图、上传、登录这四处平台差异，必须封在 `src/platform/`。
**页面代码里不准出现 `wx.` 或 `window.`。**

这是"共享 80% 代码"能成立的唯一保障。页面里只要混进一个 `wx.scanCode`，
那一页就没法复用到 H5。

### P8 · 不改设计，除非明确要求

UI 风格在 `PLAN.md` 第二节已冻结。开发中发现设计问题，
**记到 `docs/DESIGN_BACKLOG.md`，不当场改**。

否则每个开发都会顺手"优化"一点，最后产品长成谁都不认识的样子。

### P9 · 先跑通，再优化

1.0 不做性能优化。1 万用户以下，单机 Postgres + 2C4G 足够。
**性能问题等真实数据说话，不靠猜。**

同理：不做没数据支撑的缓存、不做没量支撑的分页优化。

### P10 · 可删除、可回滚

- **用户数据可删除**：位置轨迹是个人敏感信息，要有删除入口和实现（合规）
- **每个里程碑打 git tag**，任何时候能退回上一个可用状态
- **部署可回滚**：不能出现"发上去就退不回来"的发布方式

## 三、原则冲突时的优先级

```
正确性 > 可验证 > 简洁 > 性能
```

举例：为了"简洁"把分级算法抄一份到前端 → 违反 P6，**不许**。
为了"性能"绕过契约直接查库 → 违反 P5，**不许**。

---

## 四、红线（出现任何一条立即停下）

1. 代码和文档不一致，且没改文档
2. 交付里没有验证方法
3. 前端出现难度/爬升的计算逻辑
4. 页面代码里出现 `wx.` 或 `window.`
5. 手改数据库结构，没走迁移
6. 里程碑没达验收线就宣布完成
7. 未经验证就动 `docs/PLAN.md` 里冻结的设计
8. 引入没有明确理由的新依赖
