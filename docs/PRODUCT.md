# 到此一游 · 产品定位与核心模型

> 页面优先级、角色职责呈现、游客体验与首条交付验收见 [网页调整与首条验收路径](WEB_PRIORITIES.md)。保留“占山为王”的招募吸引力，地点信息和主要动作优先，已认领山峰仍开放其他山友贡献。

> 关联：[开发计划](PLAN.md) · [用户需求研究](USER_RESEARCH.md) · [权限与激励提案](PERMISSIONS.md) · [二维码](QR.md)

## 1. 定位

一个以山峰、岔路和路段为社区单元，通过现场二维码连接徒步者、登山者、越野跑者与当地维护人的户外社区。

路线数据帮助用户理解行程；二维码连接真实到访与线上参与；独立留言板积累地点的经历、路况与人与人的联系；个人记录支持回访。山大王负责将二维码通过合适形式布设到山脚、山顶等位置，并维护论坛，是产品供给和现场获客的核心角色。

核心价值：实用信息、到访纪念、与地方建立联系、帮助后来者。用户可以只阅读或保存个人记录，不必参与公开社交。

## 2. 用户与规模判断

优先用户是反复走城市周边山域的普通徒步者；兼顾偶尔出游的新手、经常登山者和越野跑者。熟悉当地的山友、领队及热心贡献者是维护人来源。人群按经验、目的、熟悉程度和本次情境区分，不能仅按年龄性别推断需求。

领域具备千万级覆盖人群的空间，但累计访问、注册、月活必须分别讨论。市场人数不等于可获取用户；是否成立取决于实地点位覆盖、内容价值、维护人持续贡献和回访。证据及局限见研究文档。

## 3. 完整线路、单段线路、山峰与点位

| 对象 | 定义与展示 | 关系 |
| --- | --- | --- |
| 完整徒步／越野线路 | 例如三峰连穿；首页与路书优先展示完整轨迹、长度、累计爬升、平均用时；不对完整线路赋单一难度等级 | 按顺序关联多个路段、山峰和岔路 |
| 单段线路／路段 | 明确起点、终点、方向及路径；例如某山脚到某山顶；定义路段难度、登顶用时和路况描述 | 同一山峰可有多个登顶路段，同一路段可被多条完整线路引用 |
| 山峰／山头 | 独立于完整线路的真实地理对象，一个山头对应一个山顶留言板 | 改线路、改峰名不产生新山头，不拆散留言和记录 |
| 岔路 | 有明确位置及来向、去向的岔路对象 | 一个岔路留言板可被多条线路引用 |
| 点位 | 山脚、山顶、岔路等实体扫码位置；一个点位一个稳定编号和短链 | 点位用于扫码，留言板用于聚合内容；不同入口可以指向同一山峰及各自登顶路段 |

山头本身没有脱离路径的唯一登顶难度或用时。山头页展示不同上山路段各自的数据。完整线路的平均用时必须注明样本与统计口径；只有算法估计时称“参考用时”，不可冒充实测均值。

“全线最难爬升段通向的顶”可作为线路中的推荐峰选择，但不再定义山头身份。GPX 切段是算法候选；同一登顶路段可能包含多个算法段，需稳定关联、版本化，不能每次重算都新建留言板。

## 4. 三类留言板

| 类型 | 主要需求 | 必须保留的地点上下文 |
| --- | --- | --- |
| 山顶 | 到此一游、登顶感受、见闻和纪念 | 山峰身份、到访记录、不同登顶路径 |
| 岔路 | 往哪里走、标识是否变化、是否可通行 | 岔路位置、来向和去向、观察时间 |
| 路段 | 路面、障碍、坡度体验、上下行情况 | 起终点、行进方向、路段内位置、观察时间 |

路书页面允许用户对具体路段描述路况，并引用同一个路段留言板。完整线路不另建第四类留言板，以免同一路段的信息分散。信息的新旧、核验与纠错机制见权限提案，尚未冻结具体交互。

## 5. 后台管线与维护人

GPX 导入 → 自动识别候选山顶及单段线路 → 网络检索峰名及来源 → 与已有山峰／路段匹配、去重 → 维护流程确认 → 发布点位和留言板 → 发二维码 → 现场布设与持续核验。

网络检索用于提出候选名称，不等于事实确认；保留来源、匹配依据与待确认状态。无法确认时展示“名称待定”，不得拿完整线路名代替峰名。

“占山为王”连接名字、贡献和山峰；岔路 NPC 指路人强调给后来者指路。维护角色负责社区服务，不代表土地所有权、封路权或对线路安全的保证。可共同维护、交接、暂停等机制属于待验证提案。

## 6. 维护人广告福利（已确认）

1. 三类留言板——山顶、岔路、路段——**每个留言板均有一个广告位**。
2. 广告由该留言板维护人上传，系统审核后展示。
3. 默认位置在**第一屏之外**；优质广告可由系统提升到第一屏。
4. 这是维护人的福利。旧版“广告位数量等于维护人等级（1/2/3/5）”不再适用；维护多块板与单块板增加广告位是两回事。
5. 收费、分成、结算和收益金额尚未确定，不将广告展示福利解释为平台承诺现金收益。

提案中另列审核流程、质量评估、首屏边界及利益冲突处理；这些细则尚未成为已确认政策。系统审核不等于维护人自行审批，也不预设必须由 AI 全自动完成。

## 7. 开发验收场景

- 两条完整线路经过同一山顶：打开同一个山顶留言板，历史记录不重复。
- 同一山峰两个上山入口：展示两条有方向的登顶路段，分别计算难度和用时。
- 同一路段从两份路书打开：读取同一块路段板；反向描述保留方向。
- 候选峰匹配到已发布山峰：复用身份，不生成第二块板；已有短链继续有效。
- 每类留言板各验证一次：默认广告第一屏外；只有审核且获提升的版本能进首屏。
- 普通用户和其他板维护人不能操作本板广告；维护人不能审批或提升自己的广告。
