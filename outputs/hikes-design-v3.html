首页为什么可以不做 tab

首页是「热门轮播 + 打卡瀑布流 + 周末活动」，它是一个内容流，不是一个需要反复回访的目的地； 而 4 个 tab 每一个都是用户带着明确目的去的（找线路 / 找地点 / 看回应 / 看自己）。 把首页放进 tab 会占掉一个高价值格子，还让四个 tab 变成五个。

代价是回首页要多一步，所以要做三件事补偿：左上角 logo 常驻且可点（所有一级页面都一样）、 点当前 tab 图标回到该 tab 顶部、以及冷启动永远落在首页。

扫一扫的醒目度

底部正中凸起 50px 钴蓝实心圆，比其余四个图标高 16px，是全站唯一一个饱和实心的常驻控件； 其余图标一律线性灰色。

另外在首页顶部保留一条 46px 的橙色窄条「我在山脚了 · 扫一扫 →」。 只有这两处——第三处会让产品看起来只会扫码，也会抢掉瀑布流的注意力。

关键交互规则

这几条决定了产品会不会走偏

四条不能松的规则

1. 用时只在同一条线路内比较。 5.2 km 的步道和 24 km 穿越不能放一个榜里。每条线路各自成最快记录， 山头页的榜只统计通往那个山头的记录。跨线路想排名，只能叫「打卡次数榜」。
2. 岔路是情报，不是情绪。 岔路页的留言必须回答"往哪走、能不能过"，带「已核验／待核验」和上报人。 三条独立确认可以自动升级为已核验；维护人核验后置顶。
3. 活动只在首页出现一张。 只显示"未来 7 天内 + 我收藏的地点或我关注的人发起"的活动，最多一张。 报名必须能退出，且报名即自动创建出发提醒。
4. 每条通知都必须能回到现场。 点「阿凯击掌了你的留言」跳到那条留言所在的地点页，而不是阿凯的主页。 这是地点型产品和普通社交产品的分界线。

回访动机与优先级

① 关系型（最强）　有人击掌、回复、接受了请求 → 消息红点
② 延迟回报型　未来信到期、你留给下一位的话被拆开
③ 竞争型　用时榜名次被超过、个人纪录被刷新
④ 责任型　我认领的山头多久没更新、有几条待核验情报
⑤ 进度型　山径拼图 3/6、想去清单、累计点位
⑥ 被动召回　分享出去的到访卡被人击掌 / 留言

第 ④ 条是这一版新加进来的：「我的山头」的维护提醒。 它让共建者有一个非情绪、非竞争的回访理由——山还在等你更新。

二维码与落地页

标牌短链 hikes.app/p/QSD02→302 跳转→ 按点位类型渲染→山头打卡页 / 岔路情报页

一个二维码 = 一个点位 = 一个稳定子页面。二维码里印短链，不印真实地址， 以后改页面结构不用重印所有标牌。服务端按 UA 分流：手机进点位页， 桌面显示"用手机扫码"页 + 编号输入框。

子页面免登录可玩（填昵称即可打卡），登录放到打卡之后。

微信能直接打开吗？能。 微信扫码用的是内置浏览器，普通 https 网页可以正常打开——这是网页版优先的价值。

四个坑：域名要国内备案；不要用 hikes:// 这类 deep link 做二维码内容； 不做诱导分享或强制下载；页面里不要再放一个"扫一扫"，需要时降级成输入点位编号。
