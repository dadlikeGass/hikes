## 一、定位与初心

前两版稿子其实是一条链的两端：

| 稿子 | 留下的东西 | 价值 |
| --- | --- | --- |
| `trail-ui.html` · 山径 Trailbook | 搜索、难度分级、分段路书、最近路况、共建认领 | **信任**：让一个陌生的地方变得敢去 |
| `social-ui-plan.md` + 概念图 · 山里见 | 扫码、到访卡、留言墙、留给下一位、山径拼图 | **温度**：让一个人在山上不孤单 |

原方案自己的定位句已经说清楚了：**「真实地点里的到访、留言和人与人的连接。扫码为主入口，路书与难度为信任基础。」**

问题在于两版各自都长成了完整的首页，谁也没接住谁——Trailbook 把"去过的人"做成了静态数据，
山里见把"路书"降级成了详情页的附属信息。

### v2 定位

> hikes 把「一条山径」当作一个有人的地方：路书让你敢去，到访让你留下，留言让下一个人不孤单。

品牌语沿用：**山里，总有人与你同频。**（副线：见山，见自己，也见同路人。／ 英文 SEE YOU OUTSIDE）

- **不是路线工具**（AllTrails / 两步路：帮你找到路、走完它）
- **不是晒图社区**（小红书：背景是山，不是山）
- hikes 的最小单位是**地点**，动态、留言、照片、用时、纪念卡全部挂在具体点位上

## 二、页面结构

五条主线 + 一个后台。入口：现场标牌扫码 · 分享链接 · 搜索 · 首页推荐。

| 主线 | 回答的问题 | 内容 |
| --- | --- | --- |
| **出发**（首页） | 我现在该做什么 | 今天去哪（附近推荐）→ 地点空间；进行中（起点打卡、点位进度、结束）→ 到访卡；今天有人在山里 → 动态详情 → 地点空间；留给下一位 → 信件详情；山况 / 天气 → 区域页 |
| **山径**（地点与路书） | 能不能去、怎么走 | 搜索筛选（区域·难度·时长·爬升）；地点空间 = 路线详情（路书 / 难度 / 装备）；分段路书与关键点位（照片·编号·来向视角）；最近路况（维护人核验 + 用户报告）；留言墙 / 到访者 / 今日现场；共建（认领·提交·巡查 → 后台审核） |
| **扫一扫** | 我已经到了 | 点位识别（标牌二维码 / 编号输入）；到达页「你是第 N 位」；留下到访卡（昵称 + 照片 + 标签）；拆信（留给下一位 / 未来信解锁）；留言墙 · 求合影 · 一起走一段；结束行程（用时记录 → 地点空间） |
| **消息** | 有人回应了你 | 留言与击掌；合影 / 同行请求的回应；信件解锁通知；我关注的山友与地点 |
| **我** | 我来过哪里 | 到访册 · 到访纪念卡；想去清单；山径拼图进度；用时记录（个人记录，不排名）；山间信箱；资料 · 隐私 · 内容管理 |
| **维护后台** | 保证路书可信 | 路线审核 · 难度复核；点位与二维码管理；内容审核 · 举报处理；维护人认领与排班；版本记录（路况变更可追溯） |

### 导航：出发 / 山径 / 扫一扫 / 消息 / 我

与原方案的两处差异：

1. **「想来」换成「山径」**。"想去"是一个状态列表，不是目的地，撑不起一个 tab；
   而搜索、难度筛选、分段路书、共建认领才是 hikes 的信任基础，需要自己的入口。
   想去 / 到过变成地点上的状态，同时收进「我」。
2. **扫一扫仍是中间凸起的主按钮**，但它不再假设用户已经在山里。

## 三、首页布局

自上而下六块，按优先级排。首页的心脏不是信息流，而是"我现在该做什么"。

| # | 模块 | 内容 | 为什么 |
| --- | --- | --- | --- |
| 1 | 问候 + 山况一行 | 天气、日落时间、路况摘要 | 回答"现在去不去得了"，不占屏。这是唯一一处环境信息，它把"打开 app"变成"要不要出门" |
| 2 | **今日主卡**（唯一主角，三态切换） | 未出发 / 在路上 / 刚结束三种面貌复用同一张卡 | 首页主角不该是动态流。它把三种真实状态收进一个位置 |
| 3 | 足迹三格 | 想去 · 到过 · 拼图 | 进度感要一直可见，但不能各占一块屏 |
| 4 | 今天有人在山里 | 动态卡，每张必须带地点与时间，可点进地点空间 | 与晒图社区的区别：动态挂在地点上，不挂在人身上 |
| 5 | 留给下一位 | 淡紫信纸 + 一句手写文案 + 现场拆开 | 同时承担"解释玩法"和"制造向往"两件事 |
| 6 | 底部导航 | 出发 / 山径 / 扫一扫（凸起）/ 消息 / 我 | 找山与上山各有入口 |

### 今日主卡三态

| 状态 | 什么时候 | 内容 |
| --- | --- | --- |
| **今天去哪**（默认） | 还没决定，多数时候 | 推荐一条附近路线（难度徽标 / 距离 / 爬升 / 耗时）+「刚刚有人从起点出发」+ 按钮`看看这条路` + `我已经到了·扫一扫` |
| **在山里** | 起点打卡后 | 换成钴蓝卡：起点时间 / 已走时长 / 点位进度 + `结束并留张到访卡` + 下撤点提示 |
| **刚结束** | 结束行程后 | 到访卡预览（印章 + 第 N 位 + 用时）+ `写一句话给下一位` |

### 扫码到达页的展开顺序

依旧遵守原方案的原则：**先轻量打卡，再展示惊喜，不一次弹出九个窗口**。

1. `#128` 印章 + 「你到了，山友，你是第 128 位在这条路上留下痕迹的人」
2. 主按钮 `留下我的到访卡`
3. 三小格：首次到访 / 本次用时 / 拼图 +1
4. 「有人给你留了一句话」→ 拆开看看
5. 留言墙（2 条预览 + 全部留言）
6. 收在底部的折叠区：写给未来的自己 · 求一张合影 · 一起走一段

## 四、UI 规范

### 色板

| 用途 | 色值 |
| --- | --- |
| 页面底 · 暖白 | `#F7F3EC` |
| 卡片 · 纸白 | `#FFFFFF` |
| 主文字 · 墨 | `#22242E` |
| 次文字 | `#6B6E7E` |
| 品牌 / 行进中 · 钴蓝 | `#3455F5` |
| 行动 / 印章 / 庆祝 · 珊瑚橙 | `#FF714E` |
| 信件 · 淡紫 | `#7B6CE8`，信纸底 `#ECE9FB` |
| 难度 · 简单（圆） | `#52B44A` |
| 难度 · 中等（方） | `#F2B62C` |
| 难度 · 困难（菱） | `#E4453A` |

**对原稿的一处修改：** 难度色从荧光 `#7DE329 / #FFDB29 / #FF5449` 降饱和为交通灯语义的
`#52B44A / #F2B62C / #E4453A`。荧光色放在暖白纸底上会盖住照片与珊瑚橙，破坏"明信片"的调性；
形状（圆 / 方 / 菱）与文字始终和颜色同时出现，色弱用户也能分辨。
森林绿 `#173E2D` 退为后台与路书表格的辅助色，不再做品牌主色——两版稿子各有一套视觉系统，这是统一后的结果。

### 字号与层级

| 层级 | 字号 / 字重 |
| --- | --- |
| 到访页主标题 | 25 / 900 |
| 卡片主标题（路线名、动态标题） | 19 / 800 |
| 区块标题 | 16.5 / 800 |
| 正文（说明、留言） | 15 / 400 |
| 次要（时间、地点、计数） | 13 / 400 |
| 标签（难度徽标、卡片眉标） | 12 / 700 |

手写体只用于信件和到访卡上的一句情绪文案，**不用于任何功能文字**——温度归温度、操作归操作。

### 形状与组件

- 卡片圆角 22 px（大卡）/ 14–16 px（小卡与缩略图）；按钮胶囊或 14 px 圆角，高度 ≥ 48 px，触控区 ≥ 44 px
- 图片 16 px 圆角，1:1 或 4:3；**人物照片优先于风景**
- 阴影 `0 1px 2px` / `0 8px 24px`，透明度 ≤ 7%
- 间距：卡片内 18 px，卡片间 14 px，区块间 18–24 px
- 核心组件：难度徽标（形状 + 文字）· 到访卡 · 信件卡 · 动态卡 · 印章 · 底部导航（中间凸起）

### 九个玩法收敛成四种动机

| 动机 | 玩法 | 回答 |
| --- | --- | --- |
| **到**（归属） | 到访纪念卡 · 第 N 位 · 第一次 · 山径拼图 | 我来过这里，这件事被记住了 |
| **留**（表达） | 留言墙 · 留给下一位 · 未来信 | 我想说点什么，而且会有人读到 |
| **遇**（连接） | 求一张合影 · 一起走一段 | 此刻这条路上，有别人在 |
| **阅**（信任） | 路书 · 难度分级 · 最近路况 · 用时记录 | 这条路到底行不行、值不值得 |

九件功能不必都做成常驻入口。常驻只留三件——**到访卡、留言墙、信件**；其余作为"到了现场才出现"的惊喜。

## 五、设计判断与待确认项

### 三个判断

1. **首页主角从"动态流"换成"今日主卡"。** 原方案首页第一屏是扫码按钮 + 山友动态，等于默认用户已经在山里，
   但大部分打开时刻是"我想出去走走"。主卡三态统一出发前 / 在路上 / 刚结束，扫码降级为主卡里的一个按钮。
2. **导航把"想来"换成"山径"。** 理由见上。
3. **动态挂在地点上，不挂在人上。** 每条动态卡必须带地点和时间，可点进"地点空间"。这决定了产品的形状：主角是山径，不是博主。

### 两个提醒

- **用时榜和品牌语是矛盾的。** 「今日登顶用时榜」把山变成了赛道，而首页写的是"慢一点也没关系，风景会等你"；
  登山场景里鼓励竞速也有安全风险。建议改成**「今日现场」**：显示谁在几点到的、现在路上有几个人，
  不排名、不比较秒数；个人用时只留作自己的记录。
- **扫码是入口，但不能是唯一入口。** 没到现场的用户打开 app 时扫码按钮是无效的，
  所以「我已经到了 · 扫一扫」永远和「看看这条路」并列出现。

### 待确认

1. 定位是否认可"路书打底、到访与留言为主"这个合成方向（还是更偏资料库 / 更偏社区）；
2. 首页主卡三态是否要真做，还是先只做"未出发"一态；
3. 难度色降饱和能否接受——它会影响已发放的实体标牌与二维码点位牌。
