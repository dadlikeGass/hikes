# 国内越野赛官方赛道 GPX —— 逐场来源与状态（2026/2027 名单）

扫表时间：2026-10-12。目标：把《国内热门越野跑赛事名单》第二节 25 场赛事的**官方赛道轨迹**找齐并下载。

## 一、结论速览

- 25 场里 **12 场拿到了官方赛道文件**，共 **64 个文件、127 万个轨迹点**，全部落在本目录，元数据见 `manifest-weibu.json`。
  其中 17 个组委会只发了 KML，已统一转成 GPX（`<trkpt>` + `<ele>`，异常高程按邻域中值修正，`manifest-weibu.json` 里 `converted_from_kml: true`），KML 原件留在 `kml-src/`。
- 官方轨迹的主要发布平台不是官网，而是**赛事报名/计时小程序的后台**。本次能批量拿到，靠的是「微步·洛基体育」平台的公开接口：

  ```
  赛事列表   https://sport.luojiweiye.com/api/getGameListApp_minapp?page=1&page_size=500&name=<关键词>
  赛道轨迹   https://sport.luojiweiye.com/api/web/track_file/web_list?game_id=<game_id>
  ```

  返回里直接给 CDN 地址（`cdn.rockysports.cn`，GPX/KML），不需要登录、不需要过验证码。崇礼 168 官网「查询下载 → 路线图」、柴古唐斯官网挂的也是这套小程序（`sport.luojiweiye.com/web/weibu/#/...`），只是官网页面本身不暴露文件地址。
- 拿不到的 13 场，原因分两类：**组委会还没发**（多为未开赛）或**只发在需要登录的渠道**（两步路·户外助手、百度网盘、公众号内小程序/二维码）。

## 四、数据口径与坑

- `distance_km` 按 trkpt haversine 累加；`gain_m` 是 5 点中值滤波 + 3 m 滞回去噪后的累计爬升，`gain_raw_m` 是原始逐点累加。
- 组委会发 KML 的那批，原始 `<ele>` 有垃圾值（例：`dasong108-2026-72k` 出现过 7 亿米海拔），转换时已按邻域中值修正；KML 原件在 `kml-src/`，需要原始数据可对比。
- 个别文件含多段 LineString，被我按段并列写成多个 `<trkseg>`；跨段不能直接连（柴古 2024 105K 若把段连起来会虚增到 138 km）。
- 组委会历年会微调赛道，**不同年份是不同的路线**；文件名已带年份，别混用。
- 轨迹版权归各组委会，此处仅作路线参考。

## 五、复现

```bash
# 1) 找赛事 id
curl -s "https://sport.luojiweiye.com/api/getGameListApp_minapp?page=1&page_size=500&name=崇礼" | python3 -m json.tool
# 2) 列官方轨迹文件
curl -s "https://sport.luojiweiye.com/api/web/track_file/web_list?game_id=5444" | python3 -m json.tool
# 3) 下载
curl -sL -o tracks/races/chongli168-2026-yunding30.gpx "https://cdn.rockysports.cn/JFXO1783804740986.gpx"
```

本目录原有 33 个文件（UTMB 中国站 + HK100）见 `README.md` / `manifest.json`；本次新增的 64 个文件见 `manifest-weibu.json`。

## 六、入库情况（2026-10-12）

`tracks/races/manifest.json` 已并入本批轨迹（93 条，含原有 33 条），跑完管线后入库：

```
python3 pipeline/build_races.py                                     # 93 条赛事路线
docker compose -f server/docker-compose.yml exec -T api python /srv/seeds/seed_race_routes.py
docker compose -f server/docker-compose.yml exec -T api python /srv/seeds/backfill_peak_points.py
docker compose -f server/docker-compose.yml exec -T api python /srv/seeds/backfill_peak_regions.py
```

- **线路库**：`routes` 里 `kind='race'` 从 33 条 → **93 条**（2023:2 / 2024:14 / 2025:20 / 2026:54 / 2027:3），
  1214 个分段、1121 个沿途山顶；本批新增 **61 条**（12 场赛事，含往届）。
- **山头库**：`route_peaks` 全部带坐标（0 条缺 lat/lng）；`points` 新增本批山脚/山顶点位，
  编号前缀登记在 `server/seeds/backfill_peak_points.py` 的 `ABBR`（当届拿干净编号，往届加 A/B），
  地区由 `backfill_peak_regions.py` 从 `race_place` 补齐（如 `WG100-*` → 中国 / 江西 / 萍乡）。
- 山顶真名仍为 NULL（按仓库约定要实地采），所以赛事山头卡片显示「待命名」。
- 海拔修复：`wutaishan-2025-21k`、`panda-2026-{105,60,25}k`、`daqingyun-2023-40k` 这 5 个文件
  官方报文的山海拔有异常/抖动，已做「越界值修复 + 5 点中值滤波」，`manifest.json` 里标了
  `ele_denoised: true` 与 `gain_note`；`wutaishan-2025-12k` 完全无海拔、距离也与组别不符，已剔除。
